# 목표비중 렌즈 v1 — 한 진실을 네 각도로

> 작성: 2026-08-14
> 선행 문서: `allocate-rail-v2.md` · `enuf-core-simplification-spec-v1.1.md` §13.2 · PR #70
> 결정 사항: 목표비중을 **종목 평면 하나로만 저장**하고 유형·국가·산업은 렌즈로 본다 ·
> 묶음 목표는 **비례 스케일**로 조정 · 보는 화면과 정하는 화면을 합친다

---

## 0. 왜

사용자 요구: **"전체에서 비중 정할 수도 있었으면. 주식 안에서도, 국가에서도, 산업에서도
비중 확인해서 다각적 판단이 가능하길."**

조사해 보니 절반은 이미 있었는데 **닿을 수가 없었다.**

| 원하는 것 | 조사 전 상태 |
|---|---|
| 국가·산업별 비중 확인 | ✅ `/allocation/country`·`/sector` 에 있음 — 설정 화면 맨 아래 작은 링크로만 연결 |
| 주식 안에서 비중 | △ 드로어 도넛만 그룹 기준, 목록 숫자는 전부 전체 대비 |
| 전체에서 비중 정하기 | ❌ 편집은 종목 한 줄씩만. 묶음 단위로 못 움직임 |
| 다각적 판단 | ❌ **보는 곳(`/allocation`)과 정하는 곳(`/allocate/settings`)이 다른 화면** |

마지막 줄이 뿌리다. 국가별로 보고 "미국이 너무 많네" 판단해도, 고치려면 다른 화면으로
나가서 종목을 하나씩 찾아야 했다. **판단과 조작이 끊겨 있으면 다각적 판단은 성립하지 않는다.**

---

## 1. 진실은 하나다

```text
                      ┌─ 유형 렌즈 ─ 주식 70% / ETF 30%
   종목 평면 목표비중 ─┼─ 국가 렌즈 ─ 미국 60% / 한국 40%
   (유일한 저장값)     └─ 산업 렌즈 ─ 반도체 25% / 소비재 15% …
```

이건 새 결정이 아니라 **PR #70 에서 이미 세운 원칙**이다.

> 국가별·산업별 목표비중은 따로 저장하지 않는다. 진실은 종목 목표비중 하나뿐이고
> 국가·산업은 그걸 묶어서 보는 렌즈다.

따로 저장하면 같은 것을 두 곳에서 정하게 되어 스펙 §13.2 가 은퇴시킨 **2층 목표비중**이
되돌아온다. 이 문서는 그 원칙을 **편집까지** 확장한다.

---

## 2. 묶음 목표 조정 — 비례 스케일

"미국 60%" 를 그 자체로 저장하지 않고, **구성 종목의 목표를 같은 비율로 움직여** 합이
60% 가 되게 만든다.

```text
  미국 = META 20% + NVDA 10%   (합 30%)
  → "미국 60%" → factor 2 → META 40% + NVDA 20%
```

종목 사이의 상대 비율은 사용자가 정한 그대로 보존된다. 저장은 여전히 평면 하나다.

### 규칙

| 상황 | 동작 |
|---|---|
| 묶음에 목표가 이미 있다 | 비례 스케일. **목표가 0인 종목은 끌어들이지 않는다**(일부러 안 정한 것) |
| 묶음에 목표가 하나도 없다 | 현재 평가액 비율로 나눈다. 평가액도 전부 0이면 균등 |
| `0%` 로 맞춤 | 그 묶음 종목의 목표를 **지운다**(0%로 정함 = 안 정함, `toStored` 와 같은 규칙) |
| 현금 묶음 | 조정 불가 — 목표를 안 채운 나머지가 곧 현금이다(§16.2) |
| 미분류·기타 | 조정 불가 — 구성이 유동적이라 오늘의 "기타"와 내일의 "기타"가 다르다 |
| 합이 100% 초과 | 저장은 하되 토스트로 알린다. 읽을 때 `capToOne` 이 비율대로 줄인다 |

### 되돌리기는 선택이 아니다

한 번 누르면 **종목 여러 개의 목표가 동시에 바뀐다.** 그래서 서버 액션이 직전 저장값을
통째로 돌려주고(`GroupTargetResult.previous`), 토스트의 되돌리기가 그걸 그대로 되쓴다
(`restoreTargets`). 하나씩 되돌리게 두면 사고다.

### 구성원은 서버에서 다시 묶는다

화면이 보낸 종목 목록을 믿지 않는다. 화면과 저장이 갈린 순간 **엉뚱한 종목의 목표가
바뀌기** 때문이다. `setGroupTarget(key, label, next)` 은 라벨만 받고 포트폴리오·메타를
다시 읽어 묶는다.

## 3. 두 가지 기준 — 전체 대비 / 이 묶음 안에서

비중은 늘 **전체 자산 대비**로 저장·계산한다. 그런데 "주식 안에서 META 가 몇 %인가"는
다른 질문이라 그것만으로는 답이 안 된다.

`withinBasis` 가 한 묶음을 100% 로 다시 정규화한다 — **저장값은 건드리지 않고 분모만**
바꾼다. 시트 상단 토글로 전환한다.

```text
전체 대비          미국 안에서
META   40%   ↔    META   67%
NVDA   20%        NVDA   33%
```

그룹 합이 0이면 0을 준다. 0으로 나눠 NaN 을 만들지 않는다.

## 4. 화면 — 보는 곳과 정하는 곳을 합쳤다

`/allocation` 이 렌즈 탭 넷을 갖는다. **종목별이 맨 앞**인 이유는 그게 진실 그 자체이기
때문이다 — 나머지 셋은 파생이다.

```text
/allocation/stock     종목별   진실. 검색형 목표비중 편집기가 여기 있다
/allocation/type      유형별   ┐
/allocation/country   국가별   ├ 묶어서 보기 + 묶음 목표 조정 + 기준 토글
/allocation/sector    산업별   ┘
/allocate/settings    설정     허들 · 투자 가능 현금 (+ 목표비중 진입 카드)
```

카테고리 카드는 `현재 % · 금액` 아래에 `목표 % · 갭` 을 보여주고, 누르면 시트가 열린다.

```text
┌ 미국 ─────────────────────────┐
│  60% · ₩60,000,000        ›   │
│  목표 70% · 10% 부족           │
└───────────────────────────────┘
        ↓ 탭
┌ 시트 ─────────────────────────┐
│  60% → 목표 70%     10% 부족   │
│  [ 70 ] %      [ 목표 맞추기 ] │
│  ─────────────────────────    │
│  [전체 대비] [미국 안에서]      │  ← 기준 토글
│  도넛 + 구성 종목(현재/목표)    │
└───────────────────────────────┘
```

**목표비중 편집기는 한 곳에만 둔다.** `/allocate/settings` 에 있던 것을
`/allocation/stock` 으로 옮겼다 — 두 곳에 두면 같은 것을 두 번 정하게 되고, 화면마다 다른
숫자를 보여주게 된다(`allocateData.ts` 주석: *"세 화면이 서로 다른 숫자를 보여주는 것이
이 앱에서 가장 위험한 버그다"*).

## 5. 미보유 목표 종목

"아직 안 샀지만 미국 20% 목표" 가 빠지면 묶음 목표 합이 실제와 어긋나고, 비례 스케일도
그 종목을 건너뛴다. 그래서 렌즈·시트·편집기 모두 **평가액 0 · `미보유` 배지**로 포함한다.

## 5.5. 범주 감사 — 도넛은 합을 100%로 다시 정규화한다 (2026-08-14 추가)

사용자 지적: *"종목별 그래프 범주에 현금이 있어서 과대계산돼."* 맞다. 원인은 렌더러다.

도넛은 recharts `Pie` 라 **넘긴 weight 합을 100% 로 다시 정규화해 그린다.** 전체 자산 대비
비중을 넘기면서 일부 범주만 담으면(합 < 100%) 모든 조각이 그만큼 부풀려 그려진다 —
라벨은 20% 인데 조각은 29% 인 식이다.

전 화면을 감사한 결과:

| 화면 | 범주 구성 | 판정 |
|---|---|---|
| `/allocation/stock` | 개별주식만 + 현금, 비중은 전체 대비 | ❌ **ETF·원자재·코인 누락 + 현금 포함** → 합 < 100% → 전 조각 부풀림 |
| `/allocation/type` | 전 유형 + 현금, total 재계산 | ✅ 합 100% |
| `/allocation/country` | 국가 + 현금 | ⚠️ 현금이 한 덩어리 → §5.6 에서 통화별로 쪼갬 |
| `/allocation/sector` | 섹터 + 현금 | ⚠️ 페이지는 현금 포함, 홈 카드(`groupByTag`)는 제외 — 규칙이 갈림(미해결) |
| 시트 도넛 | 묶음 내 정규화 | ⚠️ 평가액 0(미보유 목표)이 0% 조각으로 들어감 — 이 스펙의 회귀 |
| `sleeve/[type]` | 유형 내 정규화 | ✅ |

**고친 것**

1. `/allocation/stock` — **현금을 빼고 전 종목**(주식·ETF·원자재·코인)을 담는다.
   비중은 **종목끼리 100%** 로 다시 나눈다. 화면에 기준을 명시한다("종목끼리 100% · 현금 제외").
   목표비중 편집기는 전체 자산 대비라 기준이 다르므로 그것도 명시한다.
2. 시트 도넛에서 **평가액 0 항목 제외**. 목록에는 `미보유` 배지로 그대로 남는다.
3. ETF 분기에서 지역변수 `total` 이 prop `total`(전체 자산)을 **가리고 있었다** — 이름을
   `etfTotal` 로 바꿨다. 안 고쳤으면 "전체 대비" 기준의 분모가 조용히 ETF 합계로 바뀐다.

**안 고친 것:** 산업 렌즈의 현금 포함 여부가 페이지(포함)와 `groupByTag`(제외)로 갈린다.
홈 카드와 페이지가 다른 숫자를 낼 수 있다. 별도 판단이 필요해 남겼다.

## 5.6. 통화 현금도 배분 대상 (2026-08-14 추가)

사용자 요구: *"기존에 있는 달러·엔·원화도 자본배분할 수 있게."*

현금이 한 덩어리라 "현금의 얼마를 달러로 들고 갈지"를 정할 수가 없었다. 통화마다 한 줄로
세우고 목표를 매길 수 있게 했다.

- **저장은 예약 키** `CASH:USD` — 같은 평면 목표 맵에 들어간다. 새 저장 형식을 만들지
  않으므로 §13.2 평면 원칙이 그대로다.
- **환산**: 통화 잔액은 네이티브(₩·$·¥)라 그대로 못 더한다. `getFxToKrw` 로 ₩ 환산한 뒤
  그 비율로 `data.cash`(표시통화 합계)를 나눈다 — 합계가 대시보드와 어긋나지 않는다.
  환율을 못 받은 통화는 **뺀다**(0으로 넣으면 비중이 조용히 틀어진다).
- **현금 묶음 전체**는 여전히 조정 불가다(안 채운 나머지가 곧 현금). 통화별로만 정한다.
  통화에 배정하고 남은 몫은 "통화를 정하지 않은 현금"으로 표시한다.
- **배분 엔진은 이 키를 보지 못한다.** 후보 목록에 없기 때문이다 — 통화를 늘리는 건 매수가
  아니라 **환전**이라 buy-only 배분(§14.2)과 성격이 다르다. 목표와 갭은 렌즈에서 보여주고
  실행은 거래 입력의 환전이 맡는다.
- 종목별 편집기는 `CASH:*` 를 **제외**한다 — 통화는 종목이 아니다.

## 5.7. 보는 기준과 고치는 기준을 일치시킨다 (2026-08-14 추가)

사용자 지적: *"전체에서 누르면 이해가는데 주식 안에서 누르면 비율만 바뀌니까 어디서
바꿔야 할지 모르잖아."*

기준 토글이 **보기만** 바꾸고 입력칸은 늘 전체 대비였다. 그래서 "주식 안에서 60%네" 하고
나서 어디를 고쳐야 할지 알 수 없었다.

이제 **입력칸도 같은 기준을 따른다.**

| 보는 기준 | 입력한 값 | 저장되는 값 |
|---|---|---|
| 전체 대비 | 35% | 35% |
| 주식 안에서 (주식 목표 70%) | 50% | **70% × 50% = 35%** |

저장 형식은 늘 전체 대비 평면 하나다 — 기준은 **입력을 받는 방식**일 뿐이다. 묶음 목표가
0이면 곱할 기준이 없으므로 입력을 막고 이유를 말한다("먼저 묶음 목표부터 정해주세요").

시트의 구성 종목 줄이 조회 겸 편집이 됐다. 목록을 두 벌 두면 또 갈라지므로 한 벌로 합쳤다.

1. ~~`/allocation/stock` 도넛은 개별주식만 담는다~~ → §5.5 에서 고침(전 종목·현금 제외).
