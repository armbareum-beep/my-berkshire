## 0. 한 줄

> **고정된 "적정주가"를 저장하지 않는다. 실적이 바뀌면 매수가도 자동으로 바뀐다.**

## 1. 공식

```text
미래가격  = 현재이익력 × (1 + 성장률)^Y × 종료배수
매수가    = 미래가격 ÷ (1 + 요구수익률)^Y
기대CAGR  = (미래가격 ÷ 현재가)^(1/Y) − 1
```

기본값: `Y = 5년`, `요구수익률 = 12%` (PRD §3.2).

### 적용 불가 조건 → `null` (가짜 정밀 금지)

이익력 ≤ 0(적자) · 종료배수 ≤ 0 · 보유기간 ≤ 0 · 성장률 ≤ −100%.
현재가를 모르면 매수가는 계산하되 기대 CAGR·`buyable` 만 `null`.

---

## 2. ⚠️ `intrinsic.ts`(고든 성장)와 **다른 모형**이다

| | `intrinsic.ts` | 이 문서 |
|---|---|---|
| 식 | 오너이익 / (r − g) | EPS × (1+g)^Y × 배수 ÷ (1+r)^Y |
| 기간 | 없음(영구) | Y년 |
| 성장률 의미 | **영구** 성장률 (g < r 필수) | 향후 Y년 **EPS CAGR** (r 초과 가능) |
| 요구수익률 | max(10년물×2, 8%) 버핏식 | 기본 12% |

**성장률과 요구수익률의 의미가 다르다.** `valuation_assumptions.growth_rate`·
`discount_rate` 를 재사용하면 **조용히 틀린 값**이 나온다. 그래서 컬럼을 `er_` 접두사로
분리했다. 두 모형은 서로를 참조하지 않는다.

## 3. 데이터 모델

`valuation_assumptions` 테이블에 컬럼 6개 추가(2026-08-13 적용, 전부 nullable).

| 컬럼 | 의미 | null 일 때 |
|---|---|---|
| `er_base_metric` | `'EPS'` \| `'FCF'` | EPS |
| `er_current_metric` | 현재 주당 이익력 — **종목 통화** | 공시에서 자동(§5) |
| `er_expected_growth` | 향후 N년 이익 CAGR(소수) | 가정 없음 → 계산 안 함 |
| `er_terminal_multiple` | 종료 시점 PER/PFCF | 가정 없음 → 계산 안 함 |
| `er_holding_years` | 보유기간(년) | 5 |
| `er_required_return` | 요구수익률(소수) | 0.12 |

새 테이블을 만들지 않았다 — 키(`holding_id`, `symbol`)·RLS·`updated_at` 트리거가 이미 있다.

**성장률과 종료배수는 자동값이 없다.** 그 둘은 데이터가 아니라 견해라서 사용자가 정한다.

## 4. `/allocate` 연결 — `attractiveness` 훅

`planAllocation`(`src/lib/allocate.ts`)의 계수로 들어간다.

```text
score = gap × weightPriority × attractiveness
```

| 기대 CAGR | 계수 | 결과 |
|---|---|---|
| 요구수익률 미달 | `0` | 신규 매수 후보에서 제외 |
| 요구수익률과 같음 | `1.0` | 중립 — 순수 비중 기반 배분과 동일 |
| +5%p 초과 | `1.5` | 우선순위 상승 |

```ts
attractivenessFromCagr(cagr, required, slope = 10)
  = cagr == null ? 1
  : cagr < required ? 0
  : 1 + (cagr − required) × slope
```

### 비율이 아니라 **초과 스프레드**로 계산하는 이유

`cagr / required` 로 하면 **요구수익률을 낮게 잡은 종목이 자동으로 유리해져** 종목 간
비교가 왜곡된다. 스프레드는 기준선을 통일한다.

### 가정이 없는 종목은 계수 1.0

가정을 넣은 종목과 안 넣은 종목이 **한 화면에 섞여도 계산이 성립한다.** 밸류에이션을
쓰지 않기로 해도 이 엔진은 순수 비중 기반으로 그대로 동작한다.

### PRD §6.2 의 "목표비중 초과 시 요구수익률 12%→15%"는 여기서 처리하지 않는다

이미 `allocate.ts` 의 비중 구간 계수(`PRIORITY`)가 같은 역할을 해 **이중 적용**이 된다.

## 5. 공시 EPS 자동 연결

이익력만 공시에서 끌어온다. 비워두면 공시값을 계속 따라가므로 **실적이 갱신되면 매수
가능가도 자동으로 바뀐다**(PRD §10). 수기값을 넣으면 그게 우선한다.

| 화면 | 소스 | 비고 |
|---|---|---|
| 종목 상세 | 이미 계산된 `basisEps`(TTM 우선) | 추가 조회 없음 |
| `/allocate` | `fundamentals_cache` **캐시만** 벌크 조회 | `loadCachedEps()` |

### `/allocate` 가 캐시만 읽는 이유

`getFundamentals()` 는 캐시 미스 시 DART/EDGAR 를 호출한다. 보유 종목 수만큼 부르면
**N+1** 이 되어 배분 화면이 느려진다. 캐시에 없는 종목은 자동값 없이 넘어가고, 사용자가
그 종목 상세를 한 번 열면 채워진다.

## 6. 통화 규칙 ★ 틀리기 쉬운 곳

파이프라인은 **₩ 단일**이다(`edgar.ts` 가 미국 공시를 ₩ 로 환산). 반면 사용자는 공시에
적힌 EPS 를 **종목 통화로** 입력한다($1.35 이지 ₩1,890 이 아니다).

### 기대 CAGR 은 통화 무관

```text
기대CAGR = (EPS × (1+g)^Y × 배수 ÷ 가격)^(1/Y) − 1
```

`EPS/가격` 이 비율이라 둘을 같은 배수로 환산하면 **상쇄된다**. 따라서 환산하지 않고
**짝만 맞춘다**:

| 경우 | 계산 통화 | 환율 |
|---|---|---|
| 수기 이익력 있음 | 종목 통화 | 필요 |
| 공시 EPS 사용(기본) | ₩ (EPS·가격 둘 다 이미 ₩) | **불필요** |

초기 구현은 무조건 종목 통화로 되돌려서 **환율 조회 실패 시 해외 종목 밸류에이션을
통째로 포기**했다. 기본 경로는 애초에 환율이 필요 없었다.

### 환산이 실제로 필요한 곳은 둘뿐

- **매수 가능가 표시** — 가격이라 통화가 있다. PLTR 을 `₩237,000` 으로 보여주면 못 읽는다
- **수기 입력 라벨** — `현재 주당 이익 (EPS, $)` 처럼 단위를 못박아 혼동을 없앤다

> 테스트가 이 성질을 잠근다 — `expectedReturn.test.ts` 의 "기대 CAGR은 통화 무관"
> 블록(₩ 짝과 $ 짝이 같은 CAGR, 매수가는 통화를 따라감, 짝이 어긋나면 무너짐).

## 7. 화면 원칙

**"적정가"라고 쓰지 않는다.** 성장률·종료배수·요구수익률이 전부 사용자 가정이므로
근거를 항상 함께 노출한다 — 이 앱의 기존 방침(`intrinsic.ts` "규칙 렌즈")과 같다.

- 종목 상세: 매수 가능가 · 현재가 · 기대 CAGR · 요구수익률 + `BUYABLE`/`WAIT`
- ETF 제외 — 개별 기업 이익 모형이 성립하지 않는다
- 가정이 전부 수기라 **공시 데이터 유무와 무관하게** 노출(미보유·관심종목도 가능)
