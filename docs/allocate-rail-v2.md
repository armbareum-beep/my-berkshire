# Allocate 레일 v2 — 고르게 하지 않는다

> 작성: 2026-08-13
> 선행 문서: `allocate-redesign-v1.md`(같은 날 구현 완료) · `user-rails-v1.md` §1-1 · `design-strategy-v1.md` §4
> 결정 사항: `/allocate` 를 **3단계 레일**로 전환 · `/allocate/plan` 흡수 · 순위는 조회 화면으로 분리

---

## 0. v1 을 하고도 왜 또 바꾸나

v1 은 "한 화면 한 가지 일"을 **화면을 쪼개서** 풀었다 — 보기(`/allocate`) / 실행(`/allocate/plan`)
/ 설정(`/allocate/settings`). 체크리스트는 통과했는데 쓰는 느낌은 나아지지 않았다.

사용자 피드백: **"단계별로 게임하듯이 했으면 좋겠다. 해야 할 게 한 가지씩 나왔으면 좋겠다."**

### v1 이 남긴 것

| 증상 | 코드 근거(v1 시점) |
|---|---|
| 첫 화면이 **답이 아니라 입력값**을 크게 띄운다 | 히어로 = 투자 가능 현금. 사용자가 이미 아는 숫자다 |
| 같은 정보가 한 화면에 **두 번** | "오늘의 1순위" 카드 = "살 곳 순위" 1번 줄(로고·이름·`현재→목표` 동일) |
| 정작 답("어디에 얼마")은 **한 화면 더** | `/allocate/plan` |
| 그 화면이 **묻는 게 없다** | 금액이 투자 가능 현금으로 이미 채워져 있어 그대로 두고 결과만 봄 |

**뿌리 원인:** 화면을 쪼갠 건 맞는데, 쪼갠 조각들을 **동시에 늘어놓았다.** 카드 3개가 한
화면에 있으면 사용자는 매번 "이 중 뭘 해야 하지"를 고른다. 카드 수를 줄여도 *고르는 일*
자체는 사라지지 않는다.

> **선택지를 안 주는 게 친절이다** — `user-rails-v1.md` 서문.

이 앱은 이미 같은 문제를 거래 입력에서 풀었다(`user-rails-v1.md` §1-1):
*"폼 한 장에 다 넣으면 회계 입력이고, 한 번에 하나씩 물으면 딜 체결이다."*
자본배분만 그 레일을 안 타고 있었다.

## 1. 목표 상태

```text
┌ /allocate ── 1/3 ●○○ ────┐   ┌ 2/3 ○●○ ──────────┐   ┌ 3/3 ○○● ──────────┐
│ 얼마를 넣을까요           │ → │ 이렇게 나눕니다     │ → │ 몇 주씩 살까요      │
│  [ ₩50,000,000 ]  키패드 │   │  META  +₩12,000,000│   │  META  ×34주       │
│  +1만 +10만 +100만       │   │   목표 10%까지 3%p  │   │  BRK.B ×12주       │
│                          │   │   부족             │   │  ─────────────    │
│  [ 다음 ]                │   │  [ 이대로 진행 ]    │   │  [ 이 계획으로 등기 ]│
└──────────────────────────┘   └────────────────────┘   └────────────────────┘
                                                                  ↓ 도장 ✓
                                                        "자본배분이 등기되었습니다"
```

화면은 **하나**다. 단계가 셋일 뿐이다.

### 세 단계는 각각 다른 일을 한다

| 단계 | 묻는 것 | 왜 합칠 수 없나 |
|---|---|---|
| 1 | 얼마를 넣을까 | 사용자만 아는 값 |
| 2 | 어디에 얼마씩 | 엔진이 낸 답 — 확인이 필요하다 |
| 3 | 몇 주씩 | 금액은 주가로 나눠떨어지지 않는다. 계획은 **주수**로 등기된다 |

3단계가 2단계의 요약이었다면 뺐다. 실제로 다른 숫자라서 남긴다 — v1 의 "1순위 카드 =
순위 1번 줄" 중복을 되풀이하지 않기 위한 기준이다.

## 2. 부품을 새로 만들지 않았다

거래 입력 위저드의 부품을 그대로 쓴다. 같은 부품을 쓰므로 두 여정이 같은 앱처럼 느껴진다.

| 부품 | 출처 | 하는 일 |
|---|---|---|
| `StepShell` | `components/transactions/wizard/` | 진행 점 ●●● · ‹ 뒤로 · 큰 질문 |
| `NumberPadField` | `components/ui/NumberPad` | 키패드 시트(토스 송금 무드) |
| `SuccessOverlay` | `components/transactions/wizard/` | 도장 ✓ + "등기되었습니다" |
| `QuickAdd` | `components/ui/QuickAdd` | +1만 · +10만 알약 |

`StepShell` 에 `className` 하나만 더했다(탭바 띄우는 단계의 아래 여백). 그 외 공용 부품은
건드리지 않았다.

**엔진은 손대지 않았다** — `planAllocation`(`src/lib/allocate.ts`)·`rankRows`·
`expectedReturn`·`hurdle` 전부 그대로. 바뀐 건 표시와 진행뿐이라 기존 테스트 465개가
그대로 통과한다.

## 3. 탭바 — 1단계에만 둔다

`design-strategy-v1.md` §4 는 "여정 중" 화면에 탭바를 두지 말라고 한다. 그런데 `/allocate`
는 하단 탭 자체라, 전 단계에서 없애면 진입하자마자 갇힌다.

그래서 **1단계에만 탭바를 둔다.** 여기까지가 평시 화면이고, 금액을 확정하고 넘어가는
순간부터 여정이다. 관문 화면(시세 없음 · 목표비중 없음)도 아직 평시라 탭바를 남긴다.

---

## 4. 순위는 레일 밖으로

"살 곳 순위"(`AllocateRanking`, 주식/ETF 가로 전환)는 **지우지 않고** `/allocate/ranking`
조회 화면으로 옮겼다.

- 레일에서 뺀 이유: "지금 뭘 해야 하나"를 묻는 자리에 훑어보는 목록이 같이 있으면 답이 흐려진다.
- 지우지 않은 이유: *금액을 넣기 전에* 무엇이 매력적인지 보는 건 별개의 일이고, 투자금이
  없어도 성립한다(`rankRows` 는 투자금 0으로 상태만 뽑는다).

진입은 1단계 하단의 작은 텍스트 링크. 메인 액션과 위계가 다르다.

## 5. 최종 화면 구조

```text
/allocate            레일   1 금액 → 2 배분 → 3 주수 → 도장 ✓        탭바: 1단계만
/allocate/ranking    조회   살 곳 순위(주식 / ETF 가로 전환)
/allocate/settings   설정   목표비중 · 내 허들 · 투자 가능 현금
/allocate/plan       →     /allocate 로 리다이렉트(옛 링크 보존)
/allocate/universe   →     /allocate/settings 로 리다이렉트
/allocation/[tag]    조회   현재 자산배분 도넛 — 그대로 유지
```

**지운 것:** `components/allocate/PlanPanel.tsx`(레일 2·3단계로 흡수).

## 6. 게이미피케이션 매트릭스 통과 확인

`gamification-honest-roman-v1.md` §2 의 축하 매트릭스를 통과하는지 확인했다.

- 도장 ✓ 연출이 축하하는 것은 **"자본배분 계획을 세웠다"** — 규율 이행(✅ 축하 OK 목록의
  "자본배분 계획 완수"와 같은 줄)이다.
- **시장 결과에는 아무 연출도 붙이지 않는다.** 배분 결과 화면의 숫자(비중·기대수익률·
  남는 현금)는 그대로 정직하게 보여준다. confetti·파티클 없음(신규 의존성 0).
- "살 곳이 없어요"를 숨기지 않는다 — 2단계에서 그대로 말하고 현금으로 두는 게 맞다고 한다.

> 로망은 **연출**(도장·등기 카피)에, 정직은 **계기판**(숫자)에.
